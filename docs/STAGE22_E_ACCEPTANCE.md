# Этап 2.2-E — отчёт приёмки

Проверки в `tests/test_market_events.py` идут через `thailand.worker.process_one` на временной очереди.

- daily, manual и BUY делят один результат, HTTP нет при свежем каталоге, получатели сохраняются.
- Повторный `event_id` не создаёт второй файл.
- Событие раньше 08:00 Europe/Moscow лежит в `deferred/`, не в `pending/`; повторный wake не крутит цикл и не вызывает магазины.
- Circuit breaker переводит событие в deferred без второго прохода.
- Ошибка доставки повторяется без HTTP.
- Просроченная покупка не отправляется как текущая.
- Снимок из результата переживает `retain_thai_catalogs`.
- Подписка во время прохода получает тот же `result_id`, транспорт вызывается один раз.
- Сбой после захвата возвращает событие в pending; следующий проход один.
- Два процесса делают один вызов транспорта.
- Старый BUY job v1 с уже записанным fingerprint не сканируется снова.

Пакет F ещё не подключает Telegram, реальные BUY и серверное расписание.
