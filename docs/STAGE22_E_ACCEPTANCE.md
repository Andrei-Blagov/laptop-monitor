# Этап 2.2-E — отчёт приёмки

Проверки в `tests/test_market_events.py` идут через `thailand.worker.process_one` и `drain` на временной очереди.

- daily, manual и BUY делят один результат, HTTP нет при свежем каталоге, получатели сохраняются.
- Повторный `event_id` не создаёт второй файл.
- Событие раньше 08:00 Europe/Moscow лежит в `deferred/`, не в `pending/`; повторный wake не крутит цикл и не вызывает магазины.
- Circuit breaker переводит событие в deferred без второго прохода.
- `sender=None` и `deliver=False` оставляют событие в `delivery/`.
- Два процесса не отправляют одно событие одновременно.
- Постоянная ошибка доставки ставит `not_before` и не создаёт цикл drain; повтор после срока идёт без HTTP.
- Историческая отправка помечается `sent`. Первая цена может быть свежей, но просроченное наличие или российская цена не уходят как текущий вывод.
- `compare_markets` через worker сохраняет российскую цену `price`, характеристики, ссылки, расходы, отличия, coverage и рейтинги. Представление ссылается на эти пары.
- Новый latest и настоящая очистка RU/TH оставляют старый снимок и файл результата. Восстановление после сбоя пишет те же `references.json`.
- Без `jobs_dir` событие v2 обрабатывается из каталога конфигурации; два v1 подряд выполняются, захват снимается.
- Первая отправка сдвигает часы за срок второй: второй вывод не текущий. Без FX текущей выгоды нет, информационные наблюдения остаются свежими.
- Сохранённый результат содержит модель и цену предложения.
- Снимок из результата переживает `retain_thai_catalogs`.
- Подписка во время прохода получает тот же `result_id`, транспорт вызывается один раз.
- Живой владелец с совпавшим временем старта не перехватывается, в том числе при `stale_seconds=0`. Завершившийся процесс восстанавливается. Другой процесс с тем же PID не блокирует ни скан, ни `delivering/`.
- Другой discovery key и job v1 не сканируют параллельно с живым проходом. Два процесса не сканируют и не доставляют одно событие одновременно.
- Сбой после захвата без результата возвращает событие в pending; следующий проход один.
- Два процесса делают один вызов транспорта.
- Неотправленный BUY не попадает в delivered fingerprints. Уже подтверждённый fingerprint v1 повторно не сканируется.

Повтор между отправкой и подтверждением возможен при аварии. Пакет F ещё не подключает Telegram, реальные BUY и серверное расписание.

Среда: Docker, образ `python:3.12-slim-bookworm`, Python 3.12, контейнеры с `--network none`. Очередь перезапуска лежала во временном каталоге. Production `.env` и рабочие тома не подключались.
